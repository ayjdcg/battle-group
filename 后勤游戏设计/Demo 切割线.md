# 后勤游戏 · Demo 切割线

> 配套文件：`机制库.md`（完整机制记录）。
> 本文件只回答一件事：**demo 做什么，不做什么。**

---

## 一、Demo 只需要验证一句话

> **玩家明明只是在分配运力，却感到紧张，并且会为某个决定后悔。**

这句成立，游戏就成立，剩下的全是加法。这句不成立，加再多机制也救不回来。

**任何不服务于这句话的机制，一律后置。** 下面的所有取舍都由这把尺子量出来。

---

## 二、进与不进

### 进（缺一不可）

| 机制 | 为什么必须留 |
| --- | --- |
| 边的吞吐与在途延迟 | 稀缺与延迟的来源，没有它就没有题 |
| **后方库存有限 + 周期配额** | 没有它，"每天把运力跑满"是无条件最优解，游戏只剩横向取舍。它是"从什么时候挪"的唯一来源 |
| **配额预支** | 全 demo 最便宜的"后悔"发生器 |
| 阶梯式短缺 | 取舍的来源。线性衰减会让平均分配成为最优解 |
| 三种物资的可逆性差异 | 否则它们只是三个名字不同的同一种东西 |
| 随姿态变化的消耗 | 压力的节奏来源 |
| **战斗提前三天预告** | 它就是核心循环本身 |
| 规则式命令（下配比与优先级，不手动发车） | 操作体验的生死线 |
| 带延迟的信息 | 紧张感的主要来源 |
| **师 AI：姿态状态机 + 性格四参数** | "后悔"来自你误判了人。砍掉它，demo 就验证不了核心乐趣 |
| **人员独立环路**（国家动员 → 训练两档 → 战斗减员分流 → 简化医院规则 → 军医转化率 → 免训练自由分配） | 验证"人不是货"：人员必须有自己的输入输出闭环，且分配决策要有真实分歧（木桶效应/运力成本/预告窗口/建制消化），否则又退化成配额的翻版 |
| 战报归因 + **反事实提示** | "后悔"的直接来源，且便宜得过分 |

### 不进（记在机制库里，等 demo 验证通过再说）

| 机制 | 为什么可以砍 |
| --- | --- |
| **一切生产经营（建厂、产能、科技树）** | 不是砍，是永远不做。见机制库尺子 8 |
| **配额构成由玩家申报（带提前期）** | 压力叠加项。demo 用固定错配的构成即可，效果更强且成本为零 |
| **就地征集、缴获、跨战区拆借、用运力投资运力** | 都是流入侧的加法，会动摇尚未调稳的刻度 |
| 人员四分（军官/军医/娱乐家） | 只是让取舍的**种类**变多，核心取舍没有它们也已成立 |
| **伤员轻重两档的区分本身**（"轻伤留前线自愈、省运力"这条分支） | demo 版本负伤统一按重伤流程走（后送 → 医院 → 军医转化率），不做轻重分流。人员独立环路已经进 demo，砍的只是"轻伤可以不后送"这一个分支，不是整条回流路径 |
| 装备回收 | 同上（不进 demo） |
| 拥堵非线性、中转装卸（含医院的完整节点处理能力模型） | 同上，医院这版走简化的日处理名额+顺延惩罚，不建模节点吞吐争抢 |
| 节点囤积风险 | 同上 |
| 观察稀缺（通信投资、盯人名额） | demo 用固定延迟即可 |
| 向上级申诉 | 后期增味 |
| 假消息 / 信任经济 | 已明确暂缓 |
| 反后勤（空袭、破路） | 可作为脚本事件出现，不做成玩家要管理的系统 |

## 三、Demo 规格

### 地图

一张**固定**地图（不做随机生成）：

- 后方基地 ×1（**库存有限**，见下「后方」）
- 中转节点 ×2
- 前线节点 ×3
- 铁路 ×1（吞吐大、在途短、脆弱）
- 公路 ×2（吞吐小、在途长、韧性强）

### 后方

基地不再是无限仓库。它是「**一个有限的存量 + 一个不可控的流入**」：

- **初始库存**：一个具体的数（见「数值起点」）
- **配额**：每 7 天到货一批，数量与构成**外生固定**，玩家不能调整、不能投资、不能解锁
- **配额构成刻意与需求错配**：弹药 65% / 给养 35%，固定不变。**人员不在配额里**，走独立的国家动员+训练+回流环路（见下「人员环路」）
- **预告**：下一期给准确数量（提前 3 天），下下一期只给方向（"预计削减"），更远不给
- **预支**：可预支下一期的一部分，下一期按利息倍率扣减

**不做**：生产、建设、产能、配比申报。玩家对流入的唯一权力就是预支——**改变时点，不改变总量。**

### 部队

3 个师。每个师：

- 状态数：兵员满编率、弹药储备（天）、给养储备（天）、疲劳度、装备完好率
- 性格：激进度、囤积倾向、服从度、自知力
- 三个师的性格刻意拉开，做成**冲锋型 / 铁公鸡 / 老实人**

### 物资

3 种：**弹药、给养、人员**。人员**不**细分（军官/军医/娱乐家不进 demo），且不占配额百分比，走独立的国家动员+训练+回流环路（见「人员环路」）。

### 时间

按天推进。一局 30 天。目标：撑住 30 天不崩。

### 命令

玩家每天能做的只有五件事：

1. 调整各条线路的物资配比
2. 调整各师的补给优先级（**含人员池的分配去向，以及新兵/康复老兵的训练档位：紧急或正常**）
3. 设置各师的最低储备线
4. 回电（告知真相，影响该师的姿态决策）
5. **设定今日发运总量上限（可以低于运力，甚至为零）**，以及是否预支下一期配额

第 5 条是"挪时间"的全部操作。压低发运量等于主动浪费今天的运力，换来库存的灵活性——**只在"几天后有大战但还不知道落在谁正面"时才正确。**

**没有手动发车。没有生产。人员的分配同样走规则，不做逐个士兵的手动操作。**

### 信息

- 统一延迟 1–2 天（不做按师区分）
- 数值按"充足 / 尚可 / 紧张 / 告罄"分级显示
- 不做失联
- **基地库存对玩家完全透明、精确、无延迟**。前线的信息是模糊而滞后的，自己仓库里的东西不该是——否则玩家无法做时间维度的计算，只能瞎猜

### 界面

一屏够用，核心是**监护仪面板**：

- 一行一个师：效能条、三种物资剩余天数与下降箭头、数据的"最后更新时间"
- 交战中的师高亮
- 在途车队图标 + ETA
- **必须有的一行**：物资耗尽时刻 vs 车队 ETA 并排对比
- **后方必须有的一行**（前一行的时间维度版本）：基地库存耗尽日 vs 下批配额到货日

> 第三师弹药预计 5 日 20 时耗尽。第 14 列车预计 6 日 11 时抵达。
> 基地弹药按当前发运速度可支撑至 17 日。下批配额 19 日到货。

- 每日战报：带后勤归因 + 反事实提示

## 四、数值起点

**这些数字一定是错的**，它们只是让程序先跑起来的起点。真正的数值靠试玩磨出来（一局十分钟，可以磨很多次）。

### 消耗倍率

| 姿态 | 倍率 |
| --- | --- |
| 休整 | 0.8 |
| 底噪（固守） | 1.0 / 2.0 |
| 蛰伏 | 1.2 |
| 积极防御 | 3.0 |
| 进攻 | 6.0–8.0 |

单个高强度交战日额外吃掉约 3 天的量。

### 弹药档位（阶梯）

| 储备 | 战斗力系数 | 附加 |
| --- | --- | --- |
| ≥50% | 1.0 | — |
| 50%–20% | 0.7 | 失去主动进攻能力 |
| 20%–5% | 0.35 | — |
| <5% | 0.1 | 连续 3 天则失去建制 |

### 效能公式

```
效能 = 满编率 × 弹药档位 × 装备完好率 × (1 - 疲劳)
```

（demo 不含军官系数。）

### 运力

关键约束：**总运力约等于三个师全部处于"积极防御"时的消耗量。**

也就是说——三个师同时打防御，刚好供得上；只要有一个师转入进攻，就必然有人要挨饿。这是"永远不够"的刻度起点。

### 后方流入

把上面那个量记作 **1 D**（三个师全部积极防御时的一日总消耗）。运力刻度已经用的就是这个单位，流入刻度继续用它，两层稀缺才能直接比较。

| 参数 | 起点值 | 含义 |
| --- | --- | --- |
| 总运力 | **1.0 D / 天** | 恒定 |
| 初始库存 | **8 D** | 约八天的全线防御用量 |
| 配额周期 | **7 天** | 第 7 / 14 / 21 / 28 天到货 |
| 每期配额 | **6 D** | 平均流入 ≈ 0.86 D / 天 |
| 预支上限 | 下一期的 **50%** | |
| 预支利息 | **1.5 倍** | 预支 1 D，下期扣 1.5 D |

这套数字刻意造出三个结果：

**一、一个会被慢慢磨光的缓冲垫。** 每个周期净流失 1 D（七天吃掉 7 D，只到货 6 D）。**初始的 8 D 就是玩家这一局的全部余裕，整局都在磨它。** 若三个师全程积极防御、运力全开，库存轨迹是一条锯齿状的下坡：

```
库存(t) = 8 − t + 6 × floor(t / 7)
第 6 天 → 2 D     第 13 天 → 1 D     第 20 天 → 0 D     第 27 天 → −1 D
```

也就是说，**归零日大约落在第 20 天**，最后十天进入"有车无货"的真空。这个归零日就是这一局真正的考试日，而任何一次进攻都会把它往前推好几天。

**二、消极能活，进攻必亏。** 30 天总供给 = 8 + 4×6 = **32 D**；三个师全程积极防御的总需求 = **30 D**。刚好活下来，盈余 2 D。而进攻姿态是 6–8× 而非 3×，一个师进攻一天就要多吃 1 D 以上，加上交战日尖峰（额外约 3 天的量）——**任何一次进攻都得掏缓冲垫，而缓冲垫是不补的。** 又因为上级的进攻命令不可拒绝，赤字是必然的：玩家的任务从来不是避免赤字，而是选择在哪里赤字。

**三、两个瓶颈自动前后分工。** 前二十天库存够，瓶颈在运力（有货没车）；此后缓冲垫磨光，瓶颈转为库存（有车没货）。玩家不必同时对付两层稀缺——**他先被练熟"给谁"，再被迫开始想"什么时候"。** 这个教学顺序是数值自己长出来的，不需要专门设计。

> **调参时的唯一判定标准：玩家每天要能一眼说出"今天是车不够还是货不够"。** 说不出来，就是两个瓶颈同时咬紧了，先松开一个——通常是把每期配额调大（推后归零日），而不是加运力。

### 其他

- 铁路：日吞吐 100，在途 1 天
- 公路：日吞吐 40，在途 2 天
- 信息延迟：1 天（交战中的师 2 天）
- 战斗预告：提前 3 天

> **一个不能忽视的派生量**：战斗预告提前期（3 天）减去在途天数（1–2 天）＝ **决策窗口 1–2 天**。
>
> 这个差值决定了"压着不发"到底是不是一道题。放宽到 5 天，玩家可以等到战斗打响再发车，囤货永远不亏，纵向取舍就消失了；压到 0 或负数，提前部署变成唯一解，纵向取舍同样消失。**它必须一直很窄**，改预告提前期或在途天数时都要重算这个差值。

### 人员环路

| 参数 | 起点值 | 含义 |
| --- | --- | --- |
| 国家动员批次间隔 | **21 天**（配额周期的 3 倍） | 体现"人员流入最僵硬" |
| 训练两档 | 紧急 0 天（战斗力 ×0.5，伤亡率 ×1.3）/ 正常 7 天（满编） | 阶梯，不做连续调节 |
| 战斗减员分流 | 阵亡/失踪 30% / 负伤 70% | demo 固定比例，后续按姿态/消耗层级细化 |
| 军医转化率 | **70%** | 重伤员救回比例，起点数字 |
| 医院日处理名额 | 起点：1 D 对应人数的 20% | 超出部分顺延一天处理，顺延期间重伤组死亡率 +20% |
| 建制消化阶梯 | ≥50% 立即整编 / 20–50% 消化 2–3 天 / <20% 消化 5 天且效能额外 ×0.8 | 复用弹药阶梯的非线性思路 |
| 弹药短缺对伤亡率 | 不随弹药消耗一起下降；<5% 档位时伤亡率 ×1.2 | 保证"死亡螺旋"是真陷阱，不是账面游戏 |

这些数字和前面的运力/流入数字一样，**都是错的**，只是让人员环路先跑起来，具体刻度要靠试玩磨。

## 五、每日主循环（实现顺序）

```
1. 推进日期
2. 配额结算：到期则按固定构成注入基地库存（扣除已预支部分）
3. 国家动员结算：到期则按固定批次注入人员池（与配额周期不同步）
4. 在途队列前进，到期批次入库；训练营/医院队列前进，到期批次转出（新兵完训 / 伤员康复或彻底损失）
5. 每个师跑五步：感知 → 决策姿态 → 生成请求 → 消耗执行 → 上报
6. 有交战的师进行结算，移动战线，产生战斗减员并按固定比例分流（阵亡/失踪 vs 负伤）
7. 按玩家设定的配比与优先级从基地发出新批次（**受基地库存与今日发运上限双重限制**，含回程与伤员后送）
8. 生成战报（含归因与反事实）
9. 更新玩家可见的延迟快照与配额预告
```

九步，预计三百多行。流入层和人员环路都只是在主循环里多几次入账/出账，**不新增系统**：流入层用了第 2、7 步；人员环路用了第 3、4、6 步。

## 六、验证标准

demo 做完后，自己玩十局，逐条对照：

- [ ] 有没有出现过"我明知道他要完了，但车赶不到"的时刻？
- [ ] 有没有为某一趟车发错了人而后悔？
- [ ] 三个师的性格，玩到第三局能不能被认出来、并针对性对待？
- [ ] 有没有出现过"喂饱了他，结果把他喂死了"？
- [ ] 有没有出现过"这次我故意不给他，把他钉住"？
- [ ] 战报能不能让人明白**是我的哪个决定导致了这个结果**？
- [ ] 有没有出现过"今天我宁可让车空着，也要把这批弹药压在仓库里"？
- [ ] 有没有为一次预支后悔过？
- [ ] 有没有为一次人员分配后悔过（练早了/练晚了，或者救回来的老兵送错了师）？

第一条和第二条是及格线。其余各条命中任意两条，这个项目就值得继续做下去。

如果十局下来一条都没命中，问题多半出在**刻度**上（太松），而不是机制不够——先调刻度，不要急着加机制。调的顺序是：

1. 先调**运力**（横向压力）；
2. 运力对了但玩家从不考虑三天以后，再调**配额与初始库存**（纵向压力）；
3. **两个不要同时调。** 同时调就无法判断是哪一层在起作用，这跟"两个瓶颈不要同时咬紧"是同一个理由。

## 七、不要做的事

- 不要在 demo 验证通过前，从机制库里往回搬任何东西。
- **不要做任何形式的生产、建设或产能。** 后方只有"到货"这一个动作。
- 不要先写完整的数值表再实现。
- 不要做地图随机生成。
- 不要做美术。仪表盘用纯文字和方块条即可。
- 不要做存档、设置、主菜单。
