# 后勤指挥游戏（原型阶段）

## 项目定位

玩家是一名**战区后勤司令**。玩家不指挥战斗、不操作任何作战单位，只管理运输网络与物资分配；战斗本身是一个黑箱——它的唯一职责是消耗玩家的物资、移动战线、生成一份玩家读得懂的战报。

> 你不能命令任何人前进或后退，但你决定谁有能力动。补给就是你的操纵杆。

完整的设计动机、机制清单与数值起点都在 `后勤游戏设计/` 目录下，本 README 只负责说明当前的实现状态和入口。

## 当前状态

**设计已完成，代码尚未开始写。** 仓库里原有的"自动战斗 + 战役地图"原型（兵团编组、单位自动混战）已经整体移除——那是另一个游戏方向，跟后勤指挥这个定位不是同一个东西，继续留着只会互相干扰。

如果你要开始写代码，直接照 `后勤游戏设计/技术实现方案.md` 的里程碑顺序（M0 → M9）做，不需要重新做设计判断。

## 文档阅读顺序

1. `后勤游戏设计/机制库.md`：完整机制记录，回答"为什么这样设计"。**不代表全部要实现**，是设计仓库。
2. `后勤游戏设计/Demo 切割线.md`：这一版 demo 具体做什么、不做什么，以及全部数值起点。
3. `后勤游戏设计/技术实现方案.md`：把前两份文档翻译成可以逐步验证的实现步骤——文件清单、数据结构、每日主循环的函数签名、里程碑与验收标准。**照这份文件写代码。**

## 运行

项目用 Vite 提供本地开发服务器，逻辑用原生 JavaScript 编写，暂无框架依赖。

- `npm install`：安装开发依赖；
- `npm run dev`：启动开发服务器（目前没有页面入口，实现 `logistics-demo.html` 后需要在 `vite.config.js` 里把它加回 `rollupOptions.input`）；
- `npm run build`：生成可部署的静态文件到 `dist/`。

测试脚本会在 `logistics-core.test.js` 出现后加回 `package.json`（`node logistics-core.test.js`）。
